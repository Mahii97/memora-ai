# Local Retrieval-Augmented Generation

## Architecture

MemoraAI first retrieves evidence with the existing BM25 and semantic-vector paths, fuses the candidates, and reranks the hybrid top 20 with the local CrossEncoder. `RAGService` reuses that `HybridEngine` and takes its final top results; it does not duplicate retrieval.

```text
Question -> BM25 + vectors -> hybrid top 20 -> CrossEncoder -> top 5
         -> bounded context -> local LLM -> answer + source citations
```

Generation is optional. If `LLM_MODEL` is empty, the Ollama service is unavailable, or generation fails, `/ask` returns the retrieved excerpts and scores with `rag_enabled: false` and a generation status/message. There is no cloud-provider fallback.

## Local runtime and model configuration

`LLMService` is the runtime abstraction used by the application. The current adapter talks to Ollama's local `/api/tags` and `/api/chat` endpoints; business logic does not call an Ollama client directly. The endpoint is restricted to loopback addresses to prevent retrieved private context from being sent to a remote host.

No model is assumed by default. Configure `backend/.env` after installing a model locally:

```dotenv
LLM_PROVIDER=ollama
LLM_MODEL=qwen2.5:3b
LLM_BASE_URL=http://127.0.0.1:11434
LLM_TIMEOUT_SECONDS=120
```

The model above is an example, not a project default. At implementation time the local Ollama runtime was available and listed `qwen2.5:3b` and `qwen2.5:7b-instruct`; use any model installed on the user's machine that is compatible with Ollama.

## Installation and startup

Install Ollama separately from its official installer. MemoraAI does not install or launch runtime software automatically. In PowerShell:

```powershell
ollama pull qwen2.5:3b
ollama list
```

Start the Ollama application/runtime, then verify `http://127.0.0.1:11434/api/tags` responds locally. On Windows, installing Ollama typically starts its background service; `ollama run qwen2.5:3b` can also start an interactive model session. The model name configured in `.env` must exactly match a name shown by `ollama list`/`/api/tags`.

Install backend Python packages and run the API from `backend/`:

```powershell
..\.venv\Scripts\python.exe -m pip install -r requirements.txt
..\.venv\Scripts\python.exe -m uvicorn main:app --reload
```

Leave `LLM_MODEL=` empty for retrieval-only behavior. Do not use an external model API or point `LLM_BASE_URL` away from loopback.

## RAG pipeline and context construction

`POST /ask` calls `RAGService`, which calls the existing embedding and `HybridEngine.search_with_trace` path. The context builder uses only the final reranked results and includes each admitted chunk's source name/type, page or location, known author/date, chunk ID, reranker score, and text.

The default bounds are `RAG_MAX_CONTEXT_CHUNKS=5` and `RAG_MAX_CONTEXT_CHARACTERS=12000`. The context is passed separately from the question to the local model. Uploaded documents are treated as untrusted reference content, not instructions. The system prompt requires evidence-only answers, no invented facts, a clear insufficient-evidence response, and citations restricted to supplied source IDs. It does not request hidden chain-of-thought.

`RAG_MIN_RERANKER_SCORE` is an optional cutoff over the CrossEncoder's raw relevance score, not a confidence percentage. It is unset by default because raw scores may be negative and are not calibrated confidence values. Set a cutoff only after validating it against relevance-labeled MemoraAI queries. If there are no admitted context sources or all results fall below an explicitly configured cutoff, generation is skipped.

## Citation behavior and API fields

Every citation is constructed from a context source admitted by the context builder and contains its citation ID, source name/type, location, chunk ID, and relevance score. Unknown citation IDs generated by the model are removed from answer text. Since current content supports text-page/record locations, video timestamps are not yet available.

`POST /ask` retains the prior retrieval fields (`results`, vector/BM25/hybrid/reranker scores and explanation) and adds `answer`, `citations`, `rag_enabled`, `llm_provider`, `llm_model`, `generation_status`, `generation_message`, `context_sources`, and retrieval counts. The generation status distinguishes `generated`, `unavailable`, and `insufficient_evidence`.

## Smoke test

Run a real local query after setting `LLM_MODEL` in `backend/.env`:

```powershell
..\.venv\Scripts\python.exe smoke_test_local_rag.py --query "computer science information technology exam at IIT Roorkee"
```

The command prints hybrid sources, reranked sources, the exact bounded context, generated answer, and citations. It exits rather than pretending to generate if the configured local model is not available. Automated tests use a mocked runtime and do not require Ollama.

### Verified local smoke run

The implementation smoke run used the existing `qwen2.5:3b` Ollama model and query `computer science information technology exam at IIT Roorkee`. Generation completed locally. The model answered that the context did not contain a specific question/answer for the broad query and returned structured citations to the five supplied `CS22025.pdf` passages. This verifies runtime connectivity and grounding behavior; it is not an answer-quality benchmark.

## Troubleshooting

- **Generation unavailable:** Check Ollama is running, `LLM_BASE_URL` is loopback, `LLM_MODEL` is nonempty, and the exact model appears in `ollama list`.
- **Slow CPU generation:** Use a smaller locally installed model, reduce `RAG_MAX_CONTEXT_CHARACTERS`, or increase the request timeout.
- **Insufficient-evidence response:** Inspect returned retrieval scores and result excerpts. Calibrate `RAG_MIN_RERANKER_SCORE` using labeled evaluation data; reranker logits are not probabilities.
- **Model citation not shown:** Only IDs included in the constructed context are retained. The structured citations list contains the sources supplied to the model.
- **First model load/download:** Ollama model weights must be pulled explicitly. MemoraAI does not download a model or call a hosted API automatically.
